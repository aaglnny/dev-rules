# 鸿蒙手写风格补充规范

通用代码表达、封装克制、注释、命名和修改范围遵循 [handwritten-style-general.md](../handwritten-style-general.md)。ArkUI 状态、组件、事件和 Builder 的平台规则由 [harmony-arkui.md](harmony-arkui.md) 维护，项目工具复用由 [harmony-project.md](harmony-project.md) 和 [harmony-system-api.md](harmony-system-api.md) 维护。

## ArkUI 代码表达

- 组件树保持业务层级清晰，业务判断靠近对应 UI，不为形式统一拆出只使用一次的 Builder 或子组件。
- ArkUI 属性链每个方法单独一行，缩进和换行节奏沿用当前文件。
- 页面已有稳定布局写法时局部延续，不借功能修改批量重排组件层级或属性顺序。
- 颜色、字号、间距和图片优先使用项目资源；已有模块稳定使用数字时不做无关统一。
- 注释使用中文，只说明平台限制、兼容原因、生命周期约束或容易误删的取舍。
- 不把中文硬编码改成 Unicode 转义，不通过多余中间变量和辅助方法制造整齐感。

## struct 与成员排列规则

以下顺序只约束声明位置，不改变执行时机、调用顺序和业务逻辑。

1. 同一 `.ets` 文件中，与文件名（去掉 `.ets` 扩展名）同名的 `struct`，必须排在其他 `struct` 前面；其他 `struct` 保持原有相对顺序。`import`、顶层常量、类型声明和文件级函数不受此条限制。

2. 每个 `struct` 内按以下顺序排列：成员字段 → 初始化方法 → 生命周期方法 → `build()` → 其他方法。

3. 成员字段包括普通属性、状态属性以及 `@Event`、`@BuilderParam` 等。保持字段原有相对顺序，避免影响初始化依赖。

4. 初始化方法按实际职责认定，负责组织组件的初始准备。不能仅凭 `init` 前缀或“被初始化方法调用”进行归类；普通业务查询、刷新、事件处理等方法放在 `build()` 后面。

5. 生命周期方法指 ArkUI 提供的组件生命周期钩子，如 `aboutToAppear`、`aboutToDisappear`。

6. 其他成员方法统一放在 `build()` 后面，包括 `@Builder` 方法、`@Monitor` 方法、`@Computed` getter、事件处理方法、业务方法和辅助方法。同类别内不强制按名称排序。

7. `onReady`、`onShown`、`onHidden` 等组件属性链中的回调，保留在所属组件的属性链中，不为排序而抽成独立方法。

8. 缺少某类成员时直接跳过，不新增空方法、分区注释，不为满足排序而重命名、拆分方法或改变调用流程。

9. 新建 `struct` 遵守上述顺序。既有代码仅在明确授权的整理范围内重排，普通业务修改不得顺带整理无关成员或文件。

本文件只维护鸿蒙代码的表达方式，不重复定义平台行为、工程结构或具体系统 API。
