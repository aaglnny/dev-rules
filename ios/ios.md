# iOS 开发规范

## 适用范围与规范边界

本文件是 iOS 项目的规范入口，覆盖 Swift、UIKit、页面布局、数据存储、系统能力、工程配置和交付验证。

本规范只约束可跨业务复用的开发方式。业务模块、类名前缀、模型字段、存储键、枚举含义、计算规则和产品流程由目标项目自身文档定义。

规则参考现有 iOS 工程的稳定写法，以及 Android、HarmonyOS 规范中的工作流、职责划分、复用和验证原则。其他平台的 API、类型、目录和数据层要求不直接移植到 iOS。参考工程来源及按任务读取的文件见 [示例参考.md](示例参考.md)，无需在每次开发时加载全部示例。

既有 SwiftUI、Objective-C 或其他架构的 iOS 项目保持自己的技术边界，不因加载本文而重写为参考工程结构。纯 Swift Package、macOS 工程或独立 `.swift` 文件不能仅凭扩展名认定为 iOS 项目。

## 规范加载与冲突处理

1. 读取 `E:\rules\handwritten-style-general.md`。
2. 读取本文件 `E:\rules\ios\ios.md`。
3. 读取目标项目适用的 `AGENTS.md`、工程配置和相关模块文档。
4. 编码前读取当前模块至少一个职责相近的真实文件，核对基类、初始化、回调、依赖和存储接口。
5. 使用不熟悉或版本敏感的 API 前，核对当前 Xcode SDK 声明或 Apple 官方文档中的可用版本、参数、权限和生命周期要求。
6. 当前项目缺少同类实现或需要核对参考写法时，按 [示例参考.md](示例参考.md) 选择相关文件；示例中的业务和依赖不自动成为目标项目要求。

规范冲突时，优先保证编译、运行、业务及历史数据正确，再遵循目标项目真实 API、项目明确约束、本文平台规则和通用表达风格。示例和历史代码不是复制已知错误的理由。

## 工作流与修改范围

- 先确认仓库、分支、已有改动、应用入口、目标 Target、页面调用链和数据来源，再设计和编码。
- 需要方案审核时，按“构思方案 → 提请审核 → 分解任务 → 实施”执行。已有明确授权的必要工作继续完成，不重复请求确认。
- 只修改当前需求涉及的文件，不顺手改名、格式化、升级依赖或迁移架构。
- 功能迁移优先保留原文件结构；只为编译、依赖、平台适配和明确业务要求做必要修改，不搬运无关模板代码。
- 说明、计划、文档和新增必要注释使用中文；类名、路径和 API 标识保留英文。
- 参考工程用于只读核对。目标项目已包含同类能力时，以目标项目当前实现为准。

## 技术基线与工程配置

- 维护已有项目时沿用实际语言、UI 框架和架构，不默认引入 SwiftUI、Combine、RxSwift、MVVM、路由框架或依赖注入框架。
- 新建 UIKit 应用可参考 Swift、UIKit、SnapKit 的组合；先确认最低 iOS、Xcode、依赖管理方式、设备范围及应用身份，具体库按需要选用。
- 部署版本、Swift 语言模式和依赖版本由目标工程确定；核对 Project、Target、配置文件及依赖的最终有效设置，不固定为示例工程的历史版本。
- 调用第三方库前核对实际安装版本及 API，不凭名称猜测接口，不把相同依赖声明当成可复现安装结果。提示、键盘、图片和网络优先复用目标项目已有能力。
- CocoaPods 工程使用 `.xcworkspace`；沿用目标项目的依赖管理器，不为同一依赖同时使用 CocoaPods 和 Swift Package Manager。
- 应用项目应保存经验证的依赖锁定结果。处理 Podfile.lock 忽略或缺失问题时作为明确工程变更记录，不在无关页面任务中执行 `pod update`。
- 不随意修改 Bundle Identifier、签名团队、Entitlements、部署版本、设备支持和发布版本。
- 新增文件需检查 Target Membership 和实际工程组织方式；使用文件系统同步目录时检查同步例外，传统工程则检查文件引用与构建阶段，不机械套用另一种配置方式。
- 第三方 SDK、桥接头、资源包或符号缺失时，查明真实来源；禁止创建空实现掩盖构建缺口。

## 目录、命名与职责

`Base/` 只存放基类、公共导航、扩展和通用工具，业务模块按实际职责建立与 `Base/` 同级的目录，不在 `Base/` 下再次嵌套基础目录或业务目录。仅创建当前需求实际需要的模块，不预设固定业务目录清单。

新建项目和新增模块按此规则组织；已有旧目录的整体迁移需作为明确任务处理。

- 页面、视图、模型和数据访问代码按业务归属组织，跨业务公共能力才放入 `Base/`；不因类型名称相同就集中到一个公共目录。
- 类名前缀与页面命名沿用目标项目约定，新项目自行确定，不复制示例项目的专属前缀。
- 类型使用大驼峰，属性和方法使用小驼峰；旧项目已有前缀和历史拼写保持局部一致。
- 控制器负责页面状态、布局组织、输入事件、导航和业务调用；View、Cell、Header 负责展示与交互回调。
- 单页使用的简单 Cell 或视图可以留在页面文件中；出现真实复用、独立生命周期或明显复杂度时再拆分。
- 共享读写和统计逻辑放在已有存储入口；不在多个页面重复实现同一业务口径。
- 公共扩展只承载稳定的共用能力，不把一次性业务操作堆进公共工具类。
- 使用基类和工具前核对真实类型与方法签名，不根据文件名或项目名推测 API。
- 不为简单操作创建无实际价值的 Helper、Factory、Service、协议或泛型基类。

## Swift 表达与类型边界

- 不变值使用 `let`，需要变化才使用 `var`；内部状态按实际访问范围使用 `private`，不机械扩大可见性。
- 小范围允许 `item`、`list`、`data`、`result`；跨模块参数和多个同类对象需要明确业务含义。
- 同文件内只有一种保存操作时可以命名 `save()`，不重复堆叠文件已表达的业务名。
- 可选值表达真实缺失状态；用户输入、资源、文件、网络和异步结果使用必要解包，不用 `!` 或 `as!` 掩盖失败路径。
- 不用 `try?` 把需要上报的读写错误静默转成成功或空数据；不为每一层内部调用重复包装异常。
- `[weak self]` 依据闭包持有关系和生命周期使用，避免循环引用；使用后不再 `self!`。不能机械给所有闭包添加弱引用。
- 引用类型代理在存在反向持有关系时采用类约束与弱引用。计时器、通知观察和任务按真实生命周期释放或取消。
- 不为简单页面强行使用 actor、泛型协议或复杂响应式链；项目已有并发模式优先复用。
- 新代码显式导入直接使用的模块。修改既有 `@_exported import` 前检查 Target 内使用者，避免无关编译破坏。
- 保留附近代码的缩进和布局；无参考时使用四空格缩进。中文注释仅解释业务规则、平台限制或必要取舍，不生成作者、日期等模板注释。

## 应用入口与页面生命周期

- 沿用目标项目的 AppDelegate、SceneDelegate 或 SwiftUI App 入口；初始化集中在实际生命周期入口，不同时建立多套 Window 和根页面。
- 目标项目已有 SceneDelegate 时按 Scene 生命周期管理 Window；不从全局任取第一个窗口替代当前页面上下文。
- UIKit 页面按目标项目真实基类实现，遵守其 `super` 调用约定并复用公共能力；项目没有自定义基类时，不为套用规范强行创建。
- `viewDidLoad` 负责一次性界面创建和绑定；`viewWillAppear` 或已有回调负责需要刷新的数据，避免每次出现重复添加子视图、图层、监听或约束。
- 刷新覆盖列表、表头、汇总、图表、空状态和筛选条件，不以 `reloadData()` 代替全部刷新。
- 系统导航栏与自绘导航沿用目标模块选择，不重复叠加标题栏；导航样式变化需要同时检查返回、手势和内容安全区。
- 页面 push、present、pop、dismiss 与实际呈现关系匹配，检查导航栈和模态容器；不单凭页面存在 `presentingViewController` 就一律 dismiss。
- 页面选择结果优先沿用现有闭包或代理回传。仅为一个结果不建立事件总线。
- 根页面类型、Tab 数量、次序及入口行为由目标项目产品流程决定，不照搬示例工程。

## UIKit 布局与资源

- 使用当前项目已有布局方式；SnapKit 页面复用现有约束风格，不为普通布局新增第三方库。
- 控件加入正确父视图后再建立约束；使用 SnapKit 时，创建、更新和重建约束分别按 `makeConstraints`、`updateConstraints`、`remakeConstraints` 的实际用途选择。
- 内容以当前容器和 `safeAreaLayoutGuide` 定位，不通过屏幕宽高比例推断刘海、状态栏或底部安全区。
- 不同时设置互相冲突的左右边距、固定宽度和比例；滚动表单处理键盘遮挡、长文案和内容高度。
- 图层和图表使用布局完成后的实际尺寸，尺寸变化时更新已有图层，避免不断新增。
- Cell 复用时完整更新文字、图片、隐藏、选中和加载状态。异步图片返回应核对当前展示对象，避免串图。
- Cell 和弹层通过回调报告操作，不直接承担跨页面导航、持久化和复杂业务。
- 优先复用目标项目已有颜色、字体、尺寸和组件入口；主题标识与值由当前项目定义，不照搬示例中的常量名。
- 图片放入现有 Assets.xcassets，核对名称、大小写、倍率、Contents.json 和文件实际存在性。普通图标保持比例，裁剪背景按设计处理。
- `UIImage(named:)` 与 `UIImage(systemName:)` 不混用；系统符号和 API 都需符合最低 iOS 版本。
- XIB、Storyboard 的 Class、Module、File's Owner、Outlet 与真实类型一致；删除资源前同步检查启动配置和加载入口。
- AppIcon 目录存在不代表图标完整。版本号和应用名读取 Bundle 元信息，不在页面重复写死。
- 按项目实际支持范围验证小屏、大屏、iPad、键盘和深浅色；必要时检查文字缩放、可访问性标签与交互区域。

## 异步、图片与系统能力

- UIKit 状态和视图更新在主线程进行；图片编解码、大量文件读写和耗时计算不得阻塞主线程。
- 异步优先沿用目标模块的回调、GCD 或 Swift Concurrency 模式。使用 async/await 或新 API 前核对工具链、部署版本和接口可用性；任务取消及结果回传应符合页面生命周期。
- 并发回调不能同时修改同一数组或共享模型；通过串行处理或明确的汇总方式更新，图片顺序按产品规则保持。
- 图片选择需处理取消、失败、再次选择、数量限制和页面退出；图片尚未处理完成时，保存行为必须明确。
- PHPicker 选择图片与直接读取 PhotoKit 图库是不同能力，按实际 API 申请必要权限，不默认请求整库授权。
- 不依赖会变化的按钮标题判断动作，例如“图片”变成“图片(2)”后仍应可用；使用稳定 action、标识或局部枚举。
- 文件保存位置按是否需备份、是否可重建选择 Documents、Application Support 或 Caches；持久引用避免写死沙盒绝对路径。
- 复用目标项目已有提示和确认组件，并核对真实方法签名。加载提示结束或延时完成不代表业务成功。
- 权限拒绝、受限和取消应有符合业务的反馈；Info.plist 文案对应当前应用真实用途，不复制音视频模板的无关权限。
- 协议页使用正确应用标识、隐私或使用条款类型及实际 URL；优先 HTTPS，特殊网络例外限定到必要范围。
- 网络能力先复用目标项目现有封装；项目缺少封装时按请求规模选择系统 API 或必要依赖，不预设统一网络框架。区分请求失败、响应解析失败与业务失败，正确恢复加载和交互状态。
- 密钥和令牌不写进源码、文档或日志；需要安全存储的凭据使用平台合适能力，例如 Keychain。

## 数据模型与持久化

- 维护已有数据时复用真实读写入口；存储方案根据数据规模、查询、关联、一致性和迁移要求决定，不统一指定某个 Manager、数据库或模型结构。
- UserDefaults 优先用于少量设置；业务记录和附件按需求选择文件或数据库，不把大量图片和记录整体写入 UserDefaults 作为通用方案。
- 模型字段、CodingKeys、枚举 rawValue、存储键和日期格式属于历史数据协议，改动前检查所有读写入口及兼容方式。
- 区分无数据和解码失败；失败保留原数据，不用空列表覆盖有效历史内容。采用 Codable 时，新增非可选字段必须考虑旧记录缺失该字段时的解码。
- 保存入口应明确报告可检测的编码、文件或数据库错误。UserDefaults 的 `set` 没有可据以证明原子落盘的成功结果，不用 `synchronize()` 伪造事务或可靠性保证。
- 一次操作涉及多份关联数据时，明确统一成功条件、失败处理和防重复提交；交换独立写入顺序不能解决一致性。需要原子更新时使用相应存储能力并处理迁移。
- 需要编辑、删除或关联时使用稳定业务 ID，不用数组下标、分类文案或当前按钮标题代替实体标识。
- 清缓存仅处理可重建内容；用户创建的记录和附件不因存于 UserDefaults 或本地文件就被视为缓存。
- 影响已有用户数据时必须保留兼容或提供明确迁移，不能为绕过错误静默清数据或要求卸载应用。

具体模型、存储键、枚举值、关联约束及迁移版本写入目标项目文档，不写入本通用规范。

## 表单、数值、日期与功能闭环

- 保存前依次验证必填、格式、范围和条件必选项；失败提供明确中文反馈，恢复必要交互状态。
- 数值输入需完整解析并检查精度和允许范围，不用部分解析结果默默接受非法文本；校验规则由字段语义决定。
- 显示格式不等于计算精度。涉及精确十进制计算时，按需求选择 Decimal 或缩放整数，明确舍入和存储转换，不全局规定小数位数。
- 日期存储和查询明确 Calendar、时区、locale 及格式；固定日期格式与本地化展示区分，不把 `zh_CN` 当作时区。
- 涉及日期范围时检查闰年、跨月、跨年和时区边界；分组与筛选口径应与界面一致，空集和零值不得导致无效计算。
- 业务算法和状态转换以目标项目已确认需求为准，通过相应基准样例验证，不从示例代码推断新产品规则。
- 保存成功后返回刷新，并检查重新进入或重启后的数据；按钮、空方法或延时成功提示不算完成。

## 验证与交付

- 默认进行与改动范围匹配的静态检查，参考其他平台规范的习惯，不自动执行依赖安装、Xcode 构建、打包、模拟器安装或真机运行；用户明确要求或当前任务已授权时再执行。
- Windows 上可核对代码引用、资源、配置、数据契约和差异，但不能声称 Xcode 编译或 iOS 运行通过。
- 获得构建授权后，在有 Xcode 的 macOS 环境确认真实 workspace、Scheme、SDK、destination 和签名条件，再执行对应构建或测试，不虚构 Target 和 Scheme。
- 计算逻辑、状态转换、数据迁移和关联写入采用可复现样例或适当单元测试；简单文案、样式修改无需增加复述实现的测试。
- UI 验证覆盖实际入口、返回刷新、空状态、键盘、长内容及目标设备；异步验证覆盖取消、失败、重复提交和页面退出。
- 只提交任务相关内容，不提交凭据、Pods、构建产物和个人编辑器状态；不覆盖用户已有改动。
- 最终说明写明改变的行为、验证方式、未执行项目和实际限制。涉及存储、依赖、路由或配置变更时同步相关文档。

## 项目自身文档应记录的内容

- 实际技术栈、工具链、部署版本、依赖版本、Target 和构建方式。
- 业务模块目录、命名前缀、基类、公共组件及数据访问入口。
- 页面流程、模型字段、存储键、枚举含义、算法和业务状态规则。
- 历史数据兼容、迁移要求、验收样例及已知缺口。

这些内容随目标项目维护。通用规范负责开发方式，[示例参考.md](示例参考.md) 负责查找真实写法，二者都不代替项目需求与数据契约。
